# 安卓设备实时镜像需求文档

## 1. 文档信息

| 字段 | 内容 |
| --- | --- |
| 需求名称 | 安卓设备实时镜像 |
| 目标项目 | `evaluator` |
| 当前状态 | 需求评审稿 |
| 能力索引 | `CAPABILITY-MAP.md` |
| 首个模块Spec | `SPEC-adb-device-registry.md` |

## 2. 背景

当前PC端平台已经具备通过ADB发现安卓设备并执行评测任务的基础能力，但设备信息与评测就绪状态耦合，且缺少可在评测过程中随时开启的实时画面入口。

需要新增一项通用安卓设备镜像能力：只要安卓设备已被本机ADB识别，用户无需创建评测集、启动评测Run或安装额外安卓App，即可在WebUI中选择设备并查看流畅、低延迟的实时画面。

该能力作为评测平台的通用观察功能，首先服务于开发、调试和评测运行观察，但不得与豆泡App业务主链路耦合。

## 3. 目标

- 在评测平台顶部提供常驻的安卓设备镜像入口，并以悬浮窗展示实时画面。
- 自动发现本机ADB已连接设备，并实时反映设备连接状态。
- 在现代浏览器中流畅、低延迟地展示安卓实时画面。
- 安卓端不安装持久APK，不要求修改目标业务App。
- 镜像过程不得修改豆泡App业务状态或干扰其主流程。
- 对设备断开、ADB异常、浏览器刷新和Session结束进行可靠清理和恢复。

## 4. 非目标

首期不包含：

- 安卓设备音频同步。
- 完整会话录像和历史视频管理。
- 从WebUI向安卓注入点击、滑动、按键、文本或剪贴板。
- 公网访问、跨主机Local Agent和远程设备云。
- 面向大量观看者的SFU分发。
- iOS设备镜像。
- 绕过DRM、`FLAG_SECURE`或Android系统安全限制。
- Safari、Firefox的发布级兼容保证。

## 5. 目标用户

- 需要从PC观察安卓实时状态的开发人员。
- 需要在Web平台中查看设备运行过程的测试和评测人员。
- 需要同时管理多台ADB设备的本地调试人员。

## 6. 核心使用流程

```text
用户通过USB或无线ADB连接安卓设备
→ 本地服务发现设备
→ 用户在评测平台任意页面点击“同步真机演示”
→ 可拖拽悬浮窗展示设备及连接状态
→ 用户选择一个可镜像设备
→ 系统启动临时采集Session
→ WebUI显示实时画面
→ 用户关闭悬浮窗、关闭页面或设备断开
→ 系统释放订阅并清理临时资源
```

该流程不要求存在评测集、评测计划、评测Run或豆泡评测接口。

## 7. 功能需求

### 7.1 ADB设备发现

| ID | 需求 |
| --- | --- |
| `FR-DEVICE-001` | 系统必须发现`adb devices`可见的安卓真机和模拟器。 |
| `FR-DEVICE-002` | 系统必须展示设备serial、型号、Android版本、传输方式和连接状态；单项元数据不可用时不得隐藏设备。 |
| `FR-DEVICE-003` | 系统必须区分`ONLINE`、`OFFLINE`、`UNAUTHORIZED`和`UNKNOWN`状态。 |
| `FR-DEVICE-004` | 只有ADB原始状态为`device`的设备可以进入镜像流程。 |
| `FR-DEVICE-005` | 系统必须在设备接入、拔出、授权变化或ADB恢复后自动更新设备状态。 |
| `FR-DEVICE-006` | 所有设备操作必须显式指定serial，不得依赖ADB默认设备。 |
| `FR-DEVICE-007` | USB设备、已连接的无线ADB设备和模拟器使用统一设备契约。 |

### 7.2 常驻入口与悬浮窗

| ID | 需求 |
| --- | --- |
| `FR-UI-001` | 评测平台顶部品牌区域右侧必须常驻“同步真机演示”按钮，在评测计划、执行记录、评测集和Judge页面均可使用。 |
| `FR-UI-002` | 点击按钮后必须打开实时画面悬浮窗，并展示全部ADB可见设备及不可用原因。 |
| `FR-UI-003` | 用户必须能够选择设备、启动镜像和通过关闭悬浮窗停止当前订阅。 |
| `FR-UI-004` | 悬浮窗必须展示连接中、等待首帧、播放中、重连中、已停止和错误状态。 |
| `FR-UI-005` | 浏览器刷新或重新打开悬浮窗后必须能够重新获取设备和Session状态，不依赖前端内存作为事实来源。 |
| `FR-UI-006` | 镜像功能不得要求用户先创建或选择评测数据。 |
| `FR-UI-007` | 悬浮窗必须支持通过标题栏拖动，并限制在浏览器可视区域内。 |

### 7.3 实时画面展示

| ID | 需求 |
| --- | --- |
| `FR-VIEW-001` | WebUI必须实时展示所选安卓设备的屏幕画面。 |
| `FR-VIEW-002` | 播放器必须保持设备画面宽高比，不得因容器尺寸拉伸。 |
| `FR-VIEW-003` | 播放器必须适配设备横竖屏变化。 |
| `FR-VIEW-004` | 用户必须能够缩放、收起、恢复和全屏查看画面。 |
| `FR-VIEW-005` | 同一悬浮播放器必须能够跨评测平台页面持续显示，不因平台内部页面切换而中断。 |
| `FR-VIEW-006` | 播放失败时悬浮窗必须展示可操作的错误原因，不得永久停留在加载状态。 |

### 7.4 采集和传输

| ID | 需求 |
| --- | --- |
| `FR-STREAM-001` | 安卓端不得安装持久APK；允许通过ADB临时推送并运行`scrcpy-server`或等价临时采集组件。 |
| `FR-STREAM-002` | 采集Session结束后必须停止临时进程并清理本功能创建的临时文件。 |
| `FR-STREAM-003` | 首期视频编码必须采用H.264，默认通过WebRTC交付浏览器。 |
| `FR-STREAM-004` | PC端不得在无必要时对H.264码流二次转码。 |
| `FR-STREAM-005` | USB ADB为默认连接方式；设备已经通过无线ADB连接时允许启动镜像。 |
| `FR-STREAM-006` | 浏览器不得直接访问ADB；所有ADB访问必须由本地后端完成。 |
| `FR-STREAM-007` | 首期默认关闭音频采集和传输。 |

> 注：实现和文档中的正式组件名应统一为 `scrcpy-server`；若使用其他兼容采集组件，必须保持无持久安装、低延迟和资源隔离要求。

### 7.5 Session和订阅管理

| ID | 需求 |
| --- | --- |
| `FR-SESSION-001` | 同一设备同一时刻最多运行一个底层采集Session。 |
| `FR-SESSION-002` | 多个WebUI订阅者观看同一设备时必须复用同一画面源。 |
| `FR-SESSION-003` | 浏览器关闭或主动停止时必须释放该订阅。 |
| `FR-SESSION-004` | 最后一个订阅者离开后，系统必须在有限空闲期内停止设备采集。 |
| `FR-SESSION-005` | 设备断开后必须结束对应采集Session，并向所有订阅者广播终态。 |
| `FR-SESSION-006` | ADB恢复或设备重新连接后，用户必须能够重新启动镜像，无需重启平台。 |
| `FR-SESSION-007` | 服务退出时必须清理全部镜像Session和本功能创建的临时资源。 |
| `FR-SESSION-008` | Session必须具备稳定ID，设备serial与Session之间的关联不得串线。 |

### 7.6 错误和恢复

系统至少需要识别并展示以下错误：

- ADB未安装或不可执行。
- 设备未授权USB调试。
- 设备离线或已断开。
- 临时采集组件部署失败。
- 设备编码器不可用或启动失败。
- 等待首帧超时。
- WebRTC协商或连接失败。
- 横竖屏变化后画面恢复失败。
- 清理临时进程或文件失败。

所有服务端错误必须使用稳定的机器可读`code`和用户可理解的`message`，不得向浏览器暴露原始堆栈、未清洗ADB输出或宿主机敏感路径。

## 8. 豆泡App主链路隔离

### 8.1 禁止行为

镜像能力不得：

- 修改、重签名、覆盖安装或卸载豆泡APK。
- 启动、停止、重启、`force-stop`、清理或注入豆泡进程。
- 改变豆泡当前Activity、任务栈和前后台状态。
- 读取或修改豆泡账号、聊天、Agent、配置、Skills和评测数据。
- 注入触控、按键、文本或剪贴板事件。
- 以重启豆泡作为镜像故障恢复方式。

### 8.2 资源影响控制

实时画面编码会占用一定设备CPU、硬件编码器、内存、电量和USB带宽，因此需求目标是“业务零写入、进程零干预、资源影响受控”，而不是无法验证的绝对零开销。

必须通过以下方式控制影响：

- 单设备单采集Session。
- 限制分辨率、帧率和码率。
- 无订阅者时停止采集。
- PC端避免重复转码。
- 真机验证镜像开启前后豆泡核心功能和交互响应。

如果镜像导致豆泡新增崩溃、ANR、明显卡顿、业务状态变化或核心回归失败，该版本不得发布。

## 9. 非功能需求

### 9.1 性能

| ID | 指标 | 验收目标 |
| --- | --- | --- |
| `NFR-PERF-001` | USB场景帧率 | 目标测试设备稳定25～30 FPS |
| `NFR-PERF-002` | 端到端画面延迟 | USB场景P95不高于200 ms |
| `NFR-PERF-003` | 首帧时间 | 启动请求到浏览器首帧不超过2秒 |
| `NFR-PERF-004` | 设备变化发现 | 接入、拔出或状态变化后2秒内更新 |
| `NFR-PERF-005` | 长稳运行 | 连续运行30分钟无非预期断流 |

首期建议默认媒体参数：

```text
codec: H.264
maxFps: 30
maxSize: 1280～1600
videoBitRate: 4～8 Mbps
audio: disabled
```

具体默认值由`android-screen-capture` Spec冻结，并允许根据设备能力降级。

### 9.2 可靠性

- 设备、浏览器或ADB异常不得导致本地Web服务崩溃。
- 所有长生命周期进程和网络连接必须可取消并设置超时。
- 同一设备重复启动请求不得创建多个底层采集进程。
- 关闭Session后不得遗留不可恢复的设备占用。
- 多设备同时存在时，元数据、画面和Session不得串线。

### 9.3 安全

- 服务默认仅监听`127.0.0.1`。
- 不为任意Origin开启CORS。
- serial、Session ID和API输入必须在边界校验。
- 外部命令必须通过可执行文件和参数数组调用，不经过宿主机Shell拼接。
- 不得将ADB端口直接暴露至公网。
- 不得绕过Android系统的安全画面限制。

### 9.4 兼容性

- 首期宿主机验收目标为macOS。
- 首期浏览器验收目标为当前支持的现代Chrome和Edge。
- Android真机与模拟器使用同一后端契约；WebUI可以分组展示。
- 现有评测专用`GET /api/devices`保持兼容。
- 通用镜像设备使用新增的`/api/android/devices`资源。

## 10. 系统约束

- 功能集成在现有`evaluator` Node.js、Fastify、React和Vite工程中。
- 安卓设备访问只能发生在运行ADB的本地主机后端。
- 不新增安卓业务App或豆泡App构建变体。
- 不把评测就绪状态、豆泡版本或业务包状态加入通用设备契约。
- 每个下游模块只能依赖能力地图中的上游公开契约。

## 11. 能力拆分

| Module id | 责任 |
| --- | --- |
| `adb-device-registry` | 设备发现、状态、元数据和设备事件。 |
| `android-screen-capture` | 临时采集组件、H.264码流和设备端资源生命周期。 |
| `web-stream-gateway` | 镜像Session、WebRTC信令、订阅复用和网络回收。 |
| `device-mirror-console` | 顶部常驻入口、设备选择、可拖拽悬浮播放器和状态交互。 |

依赖顺序：

```text
adb-device-registry
→ android-screen-capture
→ web-stream-gateway
→ device-mirror-console
```

## 12. 总体验收场景

### 场景A：USB设备正常镜像

1. 已授权设备通过USB连接PC。
2. 设备在2秒内出现在WebUI。
3. 用户启动镜像。
4. 浏览器在2秒内出现首帧。
5. 画面稳定达到目标帧率和延迟。
6. 用户停止后设备临时采集资源被清理。

### 场景B：未授权设备

1. 未授权设备接入PC。
2. WebUI展示`UNAUTHORIZED`及处理提示。
3. 启动镜像入口不可用。
4. 用户完成授权后，状态自动变为`ONLINE`。

### 场景C：设备中途断开

1. 镜像正常播放。
2. 用户拔出USB。
3. WebUI在2秒内显示断开状态。
4. Session进入终态并释放PC端资源。
5. 设备重新连接后可以创建新Session。

### 场景D：多个观看者

1. 两个Web页面同时选择同一设备。
2. 后端只有一个底层采集进程。
3. 任一页面关闭不影响另一个页面。
4. 最后一个页面离开后采集自动停止。

### 场景E：豆泡主链路隔离

1. 记录豆泡当前进程、前后台状态、Activity和核心业务状态。
2. 启动并持续运行镜像。
3. 在豆泡中完成核心操作。
4. 停止镜像。
5. 豆泡无重启、无ANR、无新增崩溃、无业务数据变化，核心回归保持通过。

## 13. 发布卡点

以下任一情况发生时不得发布：

- 需要用户安装额外安卓App才能使用。
- 镜像流程会启动、停止、重启或修改豆泡。
- 设备或浏览器断开后遗留采集进程或Session。
- 同一设备产生多个不受控采集进程。
- 多设备之间画面或serial发生串线。
- USB场景达不到约定首帧、帧率或延迟目标，且没有明确降级状态。
- 豆泡核心回归出现新增失败、崩溃、ANR或明显性能退化。
- API暴露未校验输入、宿主机Shell注入或公网ADB风险。

## 14. 后续候选能力

以下能力需要独立需求评审，不默认进入首期：

- 实时音频。
- 录像、回放和时间轴。
- WebUI远程控制安卓。
- 截图和评测事件自动关联。
- 跨主机Local Agent。
- 公网设备访问和多租户鉴权。
- Safari、Firefox支持。
- iOS设备镜像。

## 15. 待确认项

1. 首期是否正式只承诺macOS，Windows和Linux作为后续兼容目标。
2. 最后一个订阅者离开后的采集空闲回收时间，建议默认5秒。
3. 是否将模拟器在WebUI中单独分组展示，后端保持统一契约。
4. 性能验收使用哪些具体安卓型号和Android版本组成基准矩阵。
