# 通用工具串行编排

## 目标

允许模型通过一次 `execute_tools` 调用声明多个已经存在的原子工具，并由运行时按顺序执行，以减少“动作—推理—动作”之间不必要的模型轮次。该能力不是 UI 专用协议，也不替代现有原子工具。

## 契约

- `execute_tools.calls` 按数组顺序执行，每项包含 `name` 与 `arguments`。
- 首版最多包含 8 个子调用，整个序列的工具执行预算最长 30 秒；等待用户完成高风险授权的时间不计入普通工具超时，避免授权后出现脱离主流程的延迟执行。
- 默认 `stopOnError=true`；任一子调用失败、超时或被熔断后停止剩余调用。
- 执行任何子调用前，先预检整个序列。只要存在未知、禁用、递归、禁止编排、参数或风险声明错误，序列不得产生部分副作用。
- 每个子调用沿用原工具的 schema、风险声明和用户确认；`execute_tools` 本身不接受汇总 `_risk`。
- 禁止递归调用 `execute_tools`，禁止把任务终止、用户问询、用户授权以及依赖循环层特殊状态机的 Todo 工具放入序列。
- 子调用不能引用前一项的返回值。依赖中间结果才能确定参数时，模型必须结束序列并在下一轮决策。
- UI 操作工具不再携带 `waitMs`。需要为页面加载或动画留出时间时，可单独调用 `wait({ms})`，也可将其作为序列子调用；`ms` 最大为 30000，屏幕文本变化时可提前结束。
- 返回每项的工具名、执行状态、耗时和结构化结果；未执行项明确标记为 skipped。

## UI 与观察

- UI 子动作仍使用原有实时定位、观察缓存失效与熔断规则。
- `ui_inspect`、`ui_screenshot` 等子调用产生的最新观察，必须和单独调用时一样进入下一轮模型上下文。
- 编排器不自动插入等待、观察或重试；这些行为必须由模型显式选择原子工具。等待使用独立的 `wait` 原子工具，不再作为各 UI 工具参数。

## 降级与兼容

- 所有可用原子工具继续独立暴露和执行，`wait` 同时支持顶层调用和 `execute_tools.calls` 子调用。
- `execute_tools` 使用现有通用工具配置开关，可独立禁用。禁用后不再暴露给模型，系统自然退回逐个原子工具调用。
- 已生成但随后被禁用的 `execute_tools` 调用返回 `TOOL_DISABLED`，不得执行任何子动作。
- 不依赖 provider 原生一次返回多个 `tool_calls`；模型历史中只记录一个合法的 `execute_tools` 调用及其聚合结果。

## 验收

1. 两个合法低风险工具只触发一次模型工具调用，并严格串行执行。
2. 后项预检失败时，前项也不执行。
3. 高风险子调用逐项展示自身 `reason` 并等待授权。
4. 子调用失败时按 `stopOnError` 决定停止或继续。
5. 重复无进展子动作仍可被现有熔断器阻止。
6. 序列中的最后一次 UI 观察可用于下一轮推理。
7. 配置关闭后工具目录不含 `execute_tools`，原子工具仍可正常调用。
