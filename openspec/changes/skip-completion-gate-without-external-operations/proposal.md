## Why

当前完成门禁把所有终止性纯文本回复都当作待确认的完成结论，导致普通问答、澄清和只读任务也弹出“任务完成确认”。门禁应由本轮是否真正代用户执行过外部操作决定，而不是由模型采用纯文本还是 `task_complete` 决定。

## What Changes

- 在任务运行期单调记录本轮是否分派过外部执行类工具调用。
- 没有任何外部操作时，完成门禁直接接受完成结论，不发布 pending 状态、不拉起应用、不发通知也不弹框。
- 发生手机界面操作、网页交互或 Shell 执行后，保留现有三选项完成确认流程。
- 明确用户澄清和风险确认都属于需要保留完成确认的用户门禁交互；只读观察、等待和任务管理本身不触发完成确认。

### New Capabilities

- `conditional-completion-gate`: 根据本轮真实工具轨迹决定是否展示任务完成确认。

## Impact

- 影响 host agent bridge 的任务级轨迹状态、工具分派记录和完成门禁入口，以及对应策略和行为测试。
- 不改变 `task_complete`、完成确认三选项或用户补充信息的数据结构。
