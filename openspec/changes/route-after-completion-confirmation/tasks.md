- [x] 2.1 在 `processCommand` 开始时初始化任务分类，并在全部完成、失败、停止及异常收尾路径中清除，避免跨任务状态泄漏。
- [x] 2.2 在单循环和规划器的工具 action 事件入口统一更新任务分类，确保所有实际执行路径使用同一策略。
- [x] 2.3 改造 `requestCompletionDecision`：仅代操作任务捕获当前/最近外部包名，并在确认 gate settle 后条件调用 `returnToPreviousApp`；问答任务不调用回跳。
- [x] 2.4 扩展 completion gate 宿主状态，支持 decision/supplement 阶段、“完成”“继续”和带用户补充内容的 continuation 消息，同时保持 AgentLoop 协议不变。
- [x] 2.5 为决策态超时增加 generation 控制：进入补充态使旧 JS/freeze-safe timer 失效，返回决策态重启 60 秒，提交或其他决策只 settle 一次。
- [x] 2.6 让完成、继续、补充提交、JS 超时、freeze-safe 超时和通知事件共用同一 settle 路由，并保证每轮完成确认重新捕获目标。
- [x] 2.7 为无目标、原生模块缺失及回跳失败增加不含页面内容的诊断日志，保证异常不阻塞 gate resolver 和任务收尾。
