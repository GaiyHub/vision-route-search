## 背景与动机

豆泡当前用 `maxHistoryItems` 滑动窗口直接丢弃较早 AgentLoop 轮次。该策略不能反映截图、无障碍树、浏览器正文和 Shell 输出之间巨大的 Token 差异，也会丢失后续用户消息、已验证结果和失败原因。

## 变更内容

- 默认启用新的上下文压缩策略，以一个模型上下文阈值触发 LLM 摘要。
- 每次构建请求时，对较早工具结果执行一次基于固定规则的单遍卸载；L2 不设置 Token 阈值或清理目标，也不进行多轮循环清理。
- 达到唯一阈值时，每个主决策轮次最多调用一次摘要模型；摘要输出为自然语言，直接保存并在下一轮用 `<context_summary>` 包装后作为 user 级历史注入。
- 摘要只承接较早历史前缀，最近 4 个完整模型轮次和最新用户消息原样保留；Todo 作为唯一独立实时状态继续注入。
- 完整原始事件继续保留，压缩和卸载只改变发送给模型的有效消息。
- 将预算估算、固定规则卸载、摘要、检查点和消息选择内聚到单一 `ContextCompressionManager` 类。
- 暂时保留原 `maxHistoryItems` 滑动窗口；配置开关关闭新策略时完整回滚到旧路径。

## 影响范围

- `AgentLoop` 的请求前消息构建入口。
- Agent 配置和设置页中的上下文压缩开关。
- Provider 的无工具摘要调用复用路径。
- 上下文管理单元测试、AgentLoop 回归测试和设置迁移测试。

## 非目标

- 不引入 JSON 摘要 Schema、分块递归摘要或摘要树。
- 不为 L2 设置单独百分比阈值或清理目标。
- 不根据重复操作、页面覆盖关系或任务进展做语义裁剪。
- 不删除原滑动窗口实现；本阶段保留其作为显式回滚路径。
