## Context

`ScreenReader.getTree()` 当前递归访问完整无障碍树，只在“已返回 200 个相关元素”后停止。大量不可见或无文本节点不会增加该计数，因此复杂页面可触发数千次跨进程属性读取。调用还同步运行在 React Native 原生模块队列，致使 JS 侧的短超时计时器也无法及时调度。截图工具同时等待图片和结构树，进一步把可用图片变成整体失败。

## Goals / Non-Goals

**Goals:**

- 让一次树观察在确定的资源预算内结束，并保留已采集的有效节点。
- 避免树遍历阻塞 React Native 原生模块队列或形成后台任务积压。
- 隔离截图图片与辅助结构树的故障，明确向上层表达部分结果。
- 保持现有数组式 `getAccessibilityTree` 调用兼容。

**Non-Goals:**

- 不改变模型系统提示词或增加每轮工具筛选规则。
- 不保证任意复杂页面都能在单次采集中返回完整无障碍树。
- 不重写 Android AccessibilityService 或引入新的视觉识别方案。

## Decisions

### 1. 原生遍历使用多维硬预算

遍历同时限制墙钟耗时、访问节点数、递归深度和返回节点数。任一预算耗尽即停止相应遍历，并在快照元数据中记录截断及首要原因。相比仅在 JS 设置 Promise 超时，这能真正停止底层 Binder 读取并避免遗留工作继续占用资源。

### 2. 新增结构化快照接口并保留旧接口

新增快照接口返回 `nodes`、`truncated`、`reason`、`visitedNodes`、`returnedNodes` 和 `durationMs`。旧 `getAccessibilityTree` 仍返回节点数组，但复用同一有界实现，避免破坏现有调用方。Agent 优先使用快照接口，并在不可用时回退旧接口。

### 3. 使用单线程执行器和单飞门禁

树遍历提交到专用单线程执行器，不占用 React Native 原生模块队列。同一时刻最多允许一个采集；并发请求快速返回 `TREE_CAPTURE_BUSY`，不排队等待过期观察。相比并行遍历，多次同时读取动态树既浪费资源也可能返回互相矛盾的快照。

### 4. 截图以图片为主结果，树为有界附加信息

截图开始时并行发起图片和结构树采集，但只给结构树一个短等待窗口。图片成功后，即使结构树超时、繁忙或异常，也返回成功图片，并附带明确的结构树不可用说明。只有图片本身失败才返回 `SCREENSHOT_UNAVAILABLE`。

### 5. 墙钟截止与取消必须下沉到原生任务

遍历预算直接检查单调时间和取消信号，而不只是由 JS 放弃等待。原生层为每次采集保存可取消任务，watchdog 到期或 JS 不再需要该观察时会设置取消信号并中断 Future。Android Binder 单次读取无法被应用层强制终止，因此树的单飞门禁仍在实际任务退出后释放，避免堆积新的树任务。

### 6. UI 动作不与树采集共用执行队列

语义点击和 ref 点击使用独立的串行动作执行器。即使某次树采集卡在不可中断的 Binder 读取中，后续动作也不在该队列后等待。

## Risks / Trade-offs

- [预算可能漏掉树尾部的重要节点] → 保留部分结果和截断原因，模型可基于截图或后续针对性观察继续；预算常量集中定义便于实机调优。
- [AccessibilityNodeInfo 单次 Binder 调用本身卡顿] → 专用执行器隔离 RN 队列；墙钟预算在该调用返回后立即生效。
- [旧调用方看不到截断元数据] → 旧接口仍获得有界部分数组；Agent 使用新接口获得完整状态。
- [单飞门禁短暂拒绝有效请求] → 返回稳定、非积压的繁忙状态；下一轮可使用已有观察而不是等待旧请求。

## Migration Plan

先发布向后兼容的原生快照接口和有界旧接口，再让 Agent 特性检测新接口。出现问题时可回退 Agent 到旧数组接口；预算实现仍保护原生队列。

## Open Questions
