## Why

豆泡当前在目标不明确或缺少关键信息时只能输出一段文字并结束本轮，无法在正在执行的任务中结构化地等待用户回答并继续。需要提供一个类似 Claude Code `AskUserQuestion` 的主动澄清入口，让模型只在确有信息缺口时提出具体问题，并把回答作为工具结果送回同一条 agent loop。

## What Changes

- 新增始终可用的 `ask_user` 工具，用于目标含糊、存在会改变执行路径的必要选择或缺少无法自行获取的信息。
- 调用工具时将豆泡拉回前台并展示自由文本澄清弹框；用户提交后关闭弹框，恢复原目标应用并继续任务。
- 将用户回答作为 `ask_user` 的结构化工具结果写入模型上下文，不创建新任务。
- 用户澄清等待不受普通动作超时和重复调用熔断限制，但仍可被停止任务中断。
- 更新系统提示词：需要澄清时主动调用 `ask_user`，普通说明/最终回答仍直接输出文字；风险授权继续使用 `confirm_action`。
- 将该协议工具设为始终启用，且不开放 UI 变化配置。

## Capabilities

### New Capabilities

- `user-clarification-tool`: 模型发起澄清、应用弹框收集自由文本、回答回流同一任务上下文及运行时等待语义。

### Modified Capabilities


## Impact

- 影响 `guidedog-agent` 的 host tool 注册、agent loop 用户等待分类、工具配置/熔断目录、系统提示词、聊天页弹框和相关测试。
- 不新增外部依赖，不改变已有 `confirm_action` 和任务完成确认的数据契约。
