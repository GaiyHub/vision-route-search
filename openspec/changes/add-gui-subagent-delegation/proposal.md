## Why

豆泡当前由主 Agent 直接规划并逐步调用手机 GUI 工具，尚不能在不扰动主推理链路的前提下验证通义 GUI 专用模型。需要增加一个可控、可观测、可随时撤回的委派边界，使验证失败或服务不可用时能够一键恢复当前稳定链路。

## What Changes

- 增加一个同步的 GUI 子 Agent 委派能力：主 Agent 可把有界的手机界面操作任务交给独立通义 UI Agent，并在工具结果返回后继续推理。
- GUI 子 Agent 使用独立模型配置、提示词、上下文和最大执行步数，但复用现有截图及 Android 动作执行能力。
- 增加默认关闭的运行时功能开关；关闭时不注册、不描述、不初始化 GUI 子 Agent，主 Agent 完整使用当前直接工具链。
- 在启用状态下保留自动降级：子 Agent 在开始执行前不可用时回到当前链路；已经产生界面副作用后不得静默重放，必须把可恢复状态返回主 Agent。
- 为委派调用定义结构化结果、进度、取消、超时、设备互斥及敏感操作确认语义。
- 增加对开关短路、同步等待、成功、失败、取消、超时和副作用后失败的验证测试与遥测。

## Capabilities

### New Capabilities

- `gui-subagent-delegation`: 主 Agent 对独立 GUI 子 Agent 的有界同步委派、执行结果和生命周期契约。
- `gui-subagent-rollout-control`: 验证阶段的默认关闭开关、硬短路、故障降级及可观测性契约。

## Impact

- 主要影响 host 层的 Agent 构造和额外工具注入、独立 GUI 子 Agent/百炼适配器，以及少量长任务超时和进度桥接代码。
- 主 `AgentLoop` 的规划循环、现有 PhoneTools、Provider 选择和关闭开关后的提示词/工具协议不改变。
- 新增百炼 GUI 模型配置与网络调用；API Key 只通过现有安全配置注入，不进入源码、日志或工具结果。
- 本变更属于实验能力，不移除或替换现有手机自动化链路，也不引入破坏性 API 变更。
