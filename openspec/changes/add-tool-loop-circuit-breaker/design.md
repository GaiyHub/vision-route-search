## Context

豆泡的 AgentLoop 以“观察屏幕—模型决策—执行工具—等待页面稳定—再次观察”为主循环。当前循环保存 `lastToolKey` 和连续重复次数，只能发现相邻且参数 JSON 完全相同的调用，并在下一轮提示模型；它既不会阻止动作，也不知道动作后页面是否变化。

OpenMinis 的 ToolLoopDetector 展示了可借鉴的架构：任务/会话级滑动窗口、稳定参数哈希、执行前 `check`、执行后 `record`、WARNING/CRITICAL 分级和提示节流。但其主要依据“相同参数 + 相同工具结果”判断无进展。手机 UI 工具经常每次都返回布尔成功，即使滚动已正常推进或点击未真正改变页面，因此豆泡必须将执行前后 UI 状态纳入判定。

本变更跨越 AgentLoop、工具调用编排、屏幕观察、Prompt 历史和任务日志，但不改变底层 AccessibilityController 的动作 API，也不引入新依赖。

## Goals / Non-Goals

**Goals:**

- 识别连续或间歇出现的等价工具动作，而不依赖参数字符串完全相同。
- 结合工具结果与执行前后 UI 状态判断“无进展”，减少误报和漏报。
- 在手机任务的有限步数内及时发出一次恢复提示，并在继续无进展时阻止等价动作。
- 阻止动作而非终止任务，使模型可以换用其他工具或路径恢复。
- 折叠重复失败历史，减少 Prompt Token、截图和等待消耗。
- 保持任务级状态隔离、日志隐私和现有 Provider/工具协议兼容。
- 在设置页提供独立「工具」页签，使每个受管工具可独立调整警告与阻断阈值。
- 让设置升级、新增工具和工具预设切换保持向前兼容。
- 通过 AgentLoop 行为测试和 Android 真机 ADB 场景共同验收。

**Non-Goals:**

- 不为 Shell、浏览器后台进程或 Watchdog 设计通用轮询熔断。
- 不增加截图语义相似度模型或新的视觉推理请求。
- 不跨任务学习阈值，不持久化熔断历史。
- 不允许用户取消确认、任务结束等安全关键工具的豁免。
- 不改变风险确认、完成确认、maxSteps 或工具本身的执行语义。
- 不因单个动作被阻断而自动宣告任务失败。

## Decisions

### 1. 使用任务级、两阶段熔断器

每个 AgentLoop 实例持有一个熔断器，并在每次任务开始时重置。熔断器提供两个概念操作：

- `checkBefore(call, observation)`：在底层工具执行前检查当前等价动作是否达到阻断阈值。
- `recordAfter(call, result, before, after, progressSignals)`：页面稳定后记录结果与前后状态，并计算是否需要产生警告。

执行前阻断可以真正避免副作用和成本；执行后记录能利用已存在的稳定等待结果。相比只在 Prompt 构建阶段计数，这一位置更接近工具执行边界，也更容易保证所有 Provider 使用相同行为。

备选方案是把循环判断完全放入模型提示词。该方案无法强制阻止动作，并且依赖模型遵守提醒，因此不采用。

### 2. 使用固定容量滑动窗口而非单一连续计数

熔断器保存最近 30 条受管工具记录。记录包含动作族、动作指纹、结果指纹、执行前后观察指纹、进展布尔值、原因代码、时间戳和可选调用标识。

检测同一动作时允许跳过其间的只读观察和任务清单更新，因此能够发现“点击—读屏—点击”的间歇循环；遇到同一动作产生不同结果或 UI 进展时结束该无进展序列。固定窗口避免长任务持续增长内存。

备选方案是只统计相邻动作。它实现简单，但模型常在重试之间插入 `read_screen` 或 `wait`，容易漏判，因此不采用。

### 3. 先归一化动作语义，再生成稳定指纹

动作指纹由工具规范名和递归稳定排序后的参数组成。归一化规则集中管理：

- 忽略 `tool_title`、调用标识、时间戳和仅用于 UI 展示的说明字段。
- 将 `click` 等已支持别名映射为规范工具名。
- nodeId 存在时优先表达节点目标；当同一 resource-id 可能对应多个网格项时，保留量化后的目标区域。
- 裸坐标按 24dp/像素级近似网格量化，使小幅漂移仍属于同一目标区域。
- 滑动按方向、起止区域和幅度区间归一化。
- 等待时长按短、中、长区间归一化；显著增加等待预算被视为恢复策略。
- 文本参数仅做安全的首尾空白与换行标准化，不对用户输入做模糊匹配。

稳定指纹可使用轻量、确定性的字符串哈希；不要求密码学安全。相比直接 `JSON.stringify`，该方案不会被键顺序或无意义字段变化绕过。

### 4. UI 进展是核心信号，工具结果是辅助信号

每个受管动作生成执行前后观察指纹。第一版观察指纹基于已序列化的无障碍树、前台包名/窗口信息和 TodoList 版本；对已知易变内容（系统时间、动画进度、瞬态计数）先做规范化。视觉模式下只复用现有“截图是否与上一帧相同”信号，不保存或哈希完整 base64。

进展判定遵循以下优先级：

1. 前台应用、窗口或主要页面结构变化，判定有进展。
2. TodoList 出现有效状态变化，判定有进展，但仅解除相关任务管理序列，不自动证明 UI 动作成功。
3. 工具产生新的、稳定的结构化结果，判定该工具调用有进展。
4. 工具返回成功但 UI 与有效结果均未变化，判定无进展。
5. 工具失败且 UI 未变化，判定无进展。

截图不同不自动代表进展，因为光标、视频和动画会持续改变像素；截图相同可增强无进展置信度。相比只比较工具结果，该设计允许同参数滚动在页面持续变化时正常执行。

### 5. 动作族提供默认值，具体工具拥有独立阈值

阈值表示“已有多少次同类无进展记录后，在下一次执行前采取动作”：

| 默认动作族 | 警告 | 阻断 | 说明 |
|---|---:|---:|---|
| 点击、长按、打开应用、全局导航 | 2 | 4 | 两次无进展后提醒；已有四次无进展时阻止下一次 |
| 输入、清空、回车、勾选 | 2 | 3 | 重复输入副作用较高，更早阻断 |
| 滚动、滑动 | 3 | 5 | 给列表加载和长页面更多空间 |
| 等待、等待节点 | 4 | 8 | 异步加载允许更宽松重试 |
| 纯观察 | 5 | 不硬阻断 | 提示必须选择推进动作或结束任务 |

动作族只用于为新工具提供初始值。运行时以规范工具名（如 `tap`、`scroll`、`type_text`）解析有效策略，每个工具均可拥有独立的 `warningThreshold` 与 `blockThreshold`；别名继承其规范工具的配置，而不会创建第二份计数或设置。

设置存储只保存相对默认策略发生变化的稀疏覆盖表：

```ts
type ToolCircuitBreakerOverride = {
  warningThreshold: number;
  blockThreshold: number;
};

type ToolCircuitBreakerOverrides = Record<string, ToolCircuitBreakerOverride>;
```

有效策略由共享的规范工具目录、动作族默认值和用户覆盖值合并得到。不得把整份默认表写入持久化数据，否则版本升级新增工具时会丢失新默认值。阈值必须为整数，且满足 `1 <= warningThreshold < blockThreshold <= historySize`；设置 UI 阻止非法组合，存储加载与运行时解析仍须重新校验并回退到该工具默认值。

用户决策、技能读取、TodoList、任务完成和任务失败属于安全豁免工具。它们仍出现在工具页并明确显示“不会熔断”，但不得启用阻断配置，以保证确认、恢复和结束路径始终可用。

OpenMinis 的 10/20/30 阈值适合更长的通用 Agent 会话，但豆泡默认主循环约 20 步；直接采用会在步数耗尽前几乎不起作用，因此使用更低的动作族阈值。

### 6. WARNING 是一次性恢复指导，BLOCKED 是结构化工具失败

达到警告阈值后，熔断器设置一条待注入反馈。下一轮最新用户消息包含动作摘要、无进展次数和有限恢复选项，例如重新读屏、在 nodeId 与坐标之间切换、检查遮罩/弹窗、返回、重新打开应用或报告失败。同一动作指纹只在跨过新的阈值桶时再次提示，避免每轮重复。

达到阻断阈值时不调用底层工具，而是产生兼容现有工具失败格式的结果：

- `ok: false`
- `error: "LOOP_BLOCKED"`
- 可读原因与无进展次数
- 被阻止的规范动作摘要
- 建议的恢复方向

阻断结果进入正常工具历史，不触发 `task_failed`。当模型选择不同动作，或相同动作之后取得 UI 进展，对应序列即可恢复。

备选方案是达到阈值直接结束任务。该方案会把可恢复的局部路径失败升级为整个任务失败，因此不采用。

### 7. 在 Prompt 中折叠循环历史

同一动作指纹的连续无进展记录在历史格式化阶段折叠为一条摘要，仅保留最近一次具体错误和累计次数。熔断器的内部滑动窗口仍保留判定所需记录，但不把全部记录发送给模型。

这同时减少历史 Token，并避免大量相同失败强化模型的错误策略。系统目标、用户修正、当前 TodoList 和最新屏幕始终不被折叠。

### 8. 复用现有可观测性通道并保护隐私

任务日志记录 `warning`、`blocked`、`recovered` 三类事件及工具动作族、动作指纹短摘要、计数和原因代码。日志不得写入完整屏幕树、截图、用户输入文本、验证码或敏感节点内容。

现有执行面板继续展示工具失败/状态。开发期间可通过过滤后的 logcat 验证熔断事件。

### 9. 设置页新增独立「工具」页签

`SettingsScreen` 在“通用、模型、经验库”之外增加“工具”页签。页签使用共享工具策略目录渲染，按点击导航、文本输入、滚动等待、查询观察和安全豁免分组；不得在 UI 中复制维护一份工具名列表。

每个受管工具行显示中文名称、规范工具名、当前预设是否启用、警告阈值和阻断阈值，并提供单工具“恢复默认”。页签顶部提供“全部恢复默认”。当前工具预设未启用的工具仍可配置并持久保存，UI 仅标记“当前预设未启用”，不能删除其设置。

步进器修改阈值时维持 `warning < block`：提高警告值碰到阻断值时同步提高阻断值；降低阻断值碰到警告值时同步降低警告值。达到滑动窗口边界后禁用继续调整，并说明阻断阈值高于任务最大步数时可能不会实际触发。

设置变更立即持久化，但正在运行的任务继续使用任务开始时取得的策略快照；下一次新任务才使用新值。这样单次任务中的判定不会因为用户中途改设置而变化。

### 10. 使用两个稳定的自动化测试接缝

AgentLoop 行为测试通过伪 Provider 返回工具调用、mock AccessibilityController 返回可控的连续页面、收集 AgentEvent 并检查下一轮 Prompt。测试只观察：底层工具是否执行、警告是否出现一次、阻断是否返回、任务能否换路继续以及新任务是否重置；不直接断言私有哈希、队列或计数器。

设置存储和策略解析器测试覆盖默认值、逐工具覆盖、非法值回退、嵌套配置迁移、新工具默认值以及运行中任务快照。设置页本身通过组件级交互测试（若现有环境支持）和 ADB 真机验收覆盖。

这种接缝覆盖完整行为，同时复用已有 AgentLoopToolResult、AgentLoopVision 和完成门测试模式。内部归一化边界通过高层输入变体（例如轻微坐标漂移）间接验证。

### 11. 逐工具可用性与元信息采用稀疏覆盖

工具预设继续提供默认可用集合，但用户可以为单个规范工具保存 `enabled` 覆盖。显式覆盖优先于预设，因此切换预设不会意外撤销用户对某个工具的独立选择。`confirm_action`、`task_complete` 和 `task_failed` 是宿主安全与终止协议的一部分，固定启用且 UI 说明不可关闭。

同一份逐工具配置允许覆盖 `label` 和 `description`。`label` 只影响设置页显示；`description` 在新任务创建时替换工具 Schema 中提供给模型的描述。工具规范名、参数属性、必填项和 handler 均不可从设置修改，避免用户输入破坏调用协议。

禁用必须在两层生效：工具定义不再传给模型；即使模型通过历史内容或幻觉生成同名调用，执行边界也返回 `TOOL_DISABLED`，不得调用底层 handler。设置仅保存相对内置定义的稀疏覆盖，非法类型、超长文本和对固定工具的禁用值逐项忽略，不影响其他工具配置。正在运行的任务继续使用创建时的工具列表和元信息快照，新任务才读取更新。

### 12. 浏览器默认描述采用任务导向的动作说明

参考 OpenMinis 的浏览器工具说明组织方式，`browser_use` 的默认描述先说明应触发该工具的真实渲染与网页交互场景，再给出 `navigate → wait_for_stable → read_page/find_elements → click/type → 验证` 的推荐流程。元素交互优先使用 `find_elements` 返回的稳定 `ref`，CSS selector 仅作为后备；截图只在文本与 DOM 信息不足时使用，避免不必要的视觉 Token。

说明只覆盖豆泡当前实现的九个动作，并明确不支持多标签页、Cookie 管理、任意 JavaScript 和后台下载，防止模型从 OpenMinis 的更大能力集合推断出不存在的调用。网页内容保持不可信数据语义，产生外部影响的操作继续通过 `confirm_action` 确认。用户仍可在工具设置中覆盖该默认描述。

## Risks / Trade-offs

- [动态页面的时钟、动画或进度导致观察指纹持续变化，掩盖真实循环] → 对已知易变字段规范化；截图变化不单独证明进展；以主要树结构和前台窗口为主。
- [页面变化但任务没有更接近目标，形成“有变化的循环”] → 第一版只解决可确定的 UI 无进展；保留 maxSteps 和完成确认作为全局上限，后续再评估语义进展。
- [坐标量化过粗导致不同目标被合并] → nodeId 优先，并保留明显不同的目标区域；使用真机网格页面校准量化尺寸。
- [坐标量化过细导致模型轻微偏移绕过] → 在行为测试加入边界坐标，并通过 ADB 重复点击场景调整。
- [工具批量调用使每个动作后的观察不完整] → 对屏幕变化工具沿用现有逐动作稳定等待，并用稳定后的 screenState 记录；无屏幕变化工具不伪造 UI 进展。
- [阈值过低影响偶发失败后的合理重试] → 先警告后阻断，并按动作族区分；阻断不终止任务，可改用其他路径恢复。
- [逐工具设置对象在浅合并或升级后缺键] → 只持久化稀疏覆盖值，通过集中解析器与版本迁移校验，不直接浅合并默认策略对象。
- [用户配置非法阈值导致永不警告或越过窗口] → UI 维持约束；加载与运行时再次校验，非法项逐工具回退默认值。
- [任务执行中修改设置造成行为突变] → 在任务开始时生成不可变策略快照，设置只对下一任务生效。
- [工具预设隐藏配置或新增工具没有设置] → 工具页展示完整注册目录并标记启用状态；新增工具按动作族自动取得默认值。
- [循环摘要丢失关键失败原因] → 始终保留最近一次具体错误和 hint，只折叠更早的重复项。
- [真机 OEM 行为与 mock 不一致] → 把 ADB 真机测试设为完成标准，至少覆盖 MIUI/当前主测试设备。

## Migration Plan

1. 新增集中式工具策略目录、熔断器与类型，并让动作族提供默认值。
2. 升级设置版本，增加稀疏逐工具覆盖值的解析、迁移和非法值回退。
3. 在设置页新增“工具”页签和逐工具阈值控件，再让 AgentLoop 在任务开始时取得策略快照。
4. 接入执行前检查、执行后记录、一次性反馈、历史折叠与隐私安全日志，替换旧的 `lastToolKey`/重复计数提示。
5. 运行设置存储/策略解析测试、AgentLoop 行为测试、完整 typecheck/test。
6. 构建并通过 ADB 安装到真机，验证设置持久化、逐工具隔离、重复点击、正常滚动、列表触底和阻断恢复。
7. 若真机误报不可接受，可回滚 AgentLoop 接入；设置迁移保留未知覆盖项且旧版本可忽略新增字段，不影响其他设置。

## Open Questions

- 24 像素/逻辑单位的坐标量化尺寸是否适合当前主测试设备，需要在 ADB 验收中校准。
- 无障碍树中需要过滤的易变字段集合以现有 ScreenSerializer 输出为起点，真机验证后再决定是否扩大。
- 工具页的中文分组和说明文案可在实现时依据实际屏幕宽度微调，不改变逐工具配置契约。
