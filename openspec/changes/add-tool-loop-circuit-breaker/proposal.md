## Why

豆泡当前只提示连续、完全相同的工具调用，无法识别坐标轻微漂移、调用间夹杂观察、工具返回成功但页面没有变化等 UI 无进展循环。这会浪费有限的任务步数、推理 Token、截图与等待时间，并可能在具有副作用的页面重复操作，因此需要在工具执行边界增加面向手机 UI 状态的分级熔断机制。

## What Changes

- 新增任务级工具熔断器，使用固定容量滑动窗口记录标准化工具调用、结果和执行前后 UI 状态。
- 引入等价动作归一化：稳定排序参数、忽略展示字段、量化相近坐标/手势/等待时长，防止轻微参数变化绕过检测。
- 以无障碍树、前台应用/窗口、工具结果和任务清单变化共同判断是否取得进展；视觉截图变化只作为辅助信号。
- 以动作族阈值作为默认值，并允许每个规范工具独立覆盖警告与阻断阈值；用户决策、完成/失败和任务清单工具保持安全豁免。
- 在设置页新增独立「工具」页签，集中展示工具状态、当前预设可用性、有效阈值，并支持单工具或全部恢复默认值。
- 工具页支持逐工具启用/禁用，并允许覆盖显示名称和提供给模型的工具描述；工具名和参数 Schema 保持只读。
- 达到警告阈值时向模型注入一次简短恢复建议；达到阻断阈值时跳过底层工具执行并返回结构化 `LOOP_BLOCKED`，但不直接结束任务。
- 折叠重复失败历史，避免同一循环逐轮占用 Prompt Token。
- 将熔断事件写入现有任务日志，记录原因代码和计数，不记录敏感页面文本、截图或输入内容。
- 增加 AgentLoop 行为测试，并在开发完成后连接 Android 真机通过 ADB 验证重复点击、正常滚动、列表触底和阻断后恢复。
- 移除现有基于 `lastToolKey` 的单一重复提示，避免两套循环判断产生冲突。

## Capabilities

### New Capabilities

- `tool-loop-circuit-breaker`: 定义豆泡工具调用的等价动作识别、UI 进展判断、分级警告、执行前阻断、恢复语义、日志与 Token 折叠要求。

### Modified Capabilities

（无——当前主规格目录没有既有能力规格，本变更新增独立能力。）

## Impact

- 影响设备 Agent 主循环、工具执行编排、屏幕观察状态、提示词历史格式化、任务日志、设置页、设置存储和相关 TypeScript 类型。
- 复用现有 AccessibilityController、屏幕稳定流程、TodoList、AgentEvent 和 Jest 测试框架，不新增运行时依赖。
- 工具执行结果新增稳定错误代码 `LOOP_BLOCKED` 和 `TOOL_DISABLED`；现有工具成功/失败协议保持兼容。
- 熔断历史仅存在于单次任务内；用户的逐工具阈值覆盖值持久化，并在新任务开始时解析为不可变策略快照。
- Android 真机与 ADB 成为该能力的最终验收环境；高风险操作只在测试应用或无敏感数据页面模拟。
