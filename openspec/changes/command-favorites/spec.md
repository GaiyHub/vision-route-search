# 指令收藏（Command Favorites）Spec

## Problem Statement

用户经常在豆泡里重复输入常用指令，但缺少“收藏”这一概念：现有“保存指令”只能长按用户消息气泡触发，存进设置（AsyncStorage），既不直观也不易发现，更无法在主页一键复用。用户希望把常用指令真正“收藏”起来：收藏行为有明确交互和反馈、收藏列表持久化到本地文件，并能从主页快速填充到聊天框再次使用。

## Solution

- 用“收藏指令”概念替代“保存指令”。任意指令表面（用户消息气泡、建议指令 chips、最近指令 chips、收藏列表条目）都可以收藏/取消收藏，收藏行为有明确视觉提示（收藏标）和 Toast 反馈。
- 收藏列表持久化到应用本地 JSON 文件，重启后保留。
- 主页「豆泡」logo 右侧新增 ⭐️ 收藏入口；点击后弹出悬浮下拉收藏列表；点击某个收藏指令自动填充到聊天框。

## User Stories

1. 作为豆泡用户，我想要长按一条用户消息指令收藏它，以便之后快速复用。
2. 作为豆泡用户，我想要在任意用户消息指令上左滑露出收藏操作，以便收藏行为更直观可发现。
3. 作为豆泡用户，我想要长按一条空态建议指令收藏它，以便把常用建议固定下来。
4. 作为豆泡用户，我想要长按一条最近指令 chip 收藏它，以便复用历史常用指令。
5. 作为豆泡用户，我想要重复收藏同一指令时不产生重复项，并给出“已收藏过”的提示，以便列表保持干净。
6. 作为豆泡用户，我想要收藏/取消收藏都有明确的 Toast 反馈，以便确认操作生效。
7. 作为豆泡用户，我想要再次长按或左滑已收藏指令可以取消收藏，以便管理收藏列表。
8. 作为豆泡用户，我想要已收藏的指令在界面上显示 ⭐️ 收藏标，以便一眼看出哪些已收藏。
9. 作为豆泡用户，我想要收藏列表保存在本地文件中并在重启应用后仍然存在，以便收藏长期有效。
10. 作为豆泡用户，我想要在主页「豆泡」logo 右侧看到 ⭐️ 收藏入口，以便快速打开收藏列表。
11. 作为豆泡用户，我想要点击 ⭐️ 入口后弹出悬浮下拉收藏列表，以便浏览已收藏指令。
12. 作为豆泡用户，我想要点击某条收藏指令后它自动填充到聊天框并关闭下拉，以便确认内容后直接发送。
13. 作为豆泡用户，我想要聊天框已有内容时，点击收藏指令会替换为收藏指令内容，以便不会产生拼接歧义。
14. 作为豆泡用户，我想要点击下拉外区域或再次点击 ⭐️ 关闭收藏下拉，以便不阻塞当前操作。
15. 作为豆泡用户，我想要收藏列表为空时显示“暂无收藏指令”的空态提示，以便理解列表为什么是空的。
16. 作为豆泡用户，我想要在收藏下拉里左滑或长按条目取消收藏，以便消息气泡被清空后仍能管理收藏。
17. 作为豆泡用户，我想要收藏列表按最新收藏优先排序，以便最新添加的指令最容易找到。
18. 作为豆泡用户，我想要收藏文件损坏或不可读时应用正常启动并显示空列表，以便不因数据异常崩溃。
19. 作为豆泡用户，我想要收藏文件写入失败时收藏操作仍即时生效，以便弱存储环境下体验不中断。
20. 作为豆泡用户，我想要旧的“保存指令”数据一次性迁移为收藏，以便升级后不会丢失已保存指令。
21. 作为豆泡用户，我想要设置页的“已保存指令”展示为收藏指令列表，以便所有入口使用同一个“收藏”概念。
22. 作为豆泡用户，我想要收藏入口和下拉列表不遮挡输入操作，以便收藏后能立即发送。

## Implementation Decisions

- 新增一个收藏 store 模块（内存态 + JSON 文件持久化），作为全功能唯一数据源：
  - 接口：`subscribe(listener)`、`getFavorites()`、`isFavorite(text)`、`toggleFavorite(text)`。
  - 数据形状：去重后的指令文本数组，最新收藏在前；以应用文档目录下的 JSON 文件（如 `favorites.json`）持久化。
  - 模块初始化时加载文件；加载失败回退为空列表；写入失败只保留内存态，不阻塞交互。
  - 存储路径可注入，便于测试使用临时目录。
- 收藏交互：
  - 用户消息指令行：左滑露出 ⭐️ 收藏操作（复用现有手势依赖，不引入新动画依赖），长按作为等价操作保留。
  - 空态建议 chips 与最近指令 chips：长按收藏/取消收藏。
  - 收藏下拉条目：点击填充聊天框；左滑或长按取消收藏。
  - 已收藏的指令在气泡/条目上显示 ⭐️ 收藏标。
- 主页入口：在「豆泡」logo 右侧增加 ⭐️ 按钮；点击切换悬浮下拉（绝对定位覆盖在头部下方），再次点击或点击外部关闭；点击条目用所选指令填充聊天框并关闭。
- 旧概念迁移：聊天页长按不再写入设置的“保存指令”；首次加载且收藏为空时，把旧的已保存指令一次性迁移进收藏文件；设置页“已保存指令”列表改为展示收藏指令。

## Testing Decisions

- 唯一测试缝：收藏 store 模块。只测外部行为（增删、去重、顺序、持久化往返、异常文件容错、订阅通知），不测内部实现细节。
- 测试用例：
  - 收藏/取消收藏切换及返回值；
  - 相同指令去重且最新在前；
  - 写入文件后重新创建 store 实例能读到相同数据；
  - 损坏或非字符串内容时回退为空列表且不抛异常；
  - 订阅者在数据变化时收到快照。
- 先例：仓库内 `TodoList`、`TodoTool` 及 store 的 Jest + ts-jest 单测风格；文件写入部分参考任务日志的本地文件先例，但路径注入化。
- UI 行为（左滑露出、下拉开合、点击填充、空态）不引入新的组件测试缝，走真机手工验收清单。

## Out of Scope

- 云同步、多端共享收藏。
- 收藏指令的重命名、排序编辑、分组/多收藏夹。
- 语音指令收藏。
- 收藏指令一键直接执行（本次只填充聊天框，由用户确认后发送）。
- 从收藏入口删除本地文件或做备份导出。

## Further Notes

- 本 spec 由用户自行同步到项目 issue tracker（GitHub）；发布时建议应用 `ready-for-agent` triage label。
- 悬浮下拉需要高于现有屏幕预览层的层级，避免被后续内容遮挡。
- 左滑交互优先使用现有手势依赖，避免新增 reanimated 等重依赖。
