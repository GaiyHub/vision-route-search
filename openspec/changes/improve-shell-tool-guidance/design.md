## Context

豆泡把模型行为分成问答类和操作类。现有问答类规则绝对禁止所有工具，而 Shell 的用途仅存在于工具描述中，因此精确计算、结构化转换等“结果仍是文字但需要执行”的任务会在看到工具描述前被路由为直接回答。用户明确要求不增加每轮工具筛选，并延续“工具细节尽量放在工具描述中”的设计原则。

## Goals / Non-Goals

**Goals:**

- 允许模型为精确、可验证的执行型信息处理任务调用工具。
- 让 `shell_execute` 描述清楚说明何时优先、何时不应调用。
- 保持普通知识问答和创作请求的直接回答体验。

**Non-Goals:**

- 不做任务级或每轮工具筛选。
- 不改变工具预设、注册顺序、权限和 Shell 运行时。
- 不把 OpenMinis 的大段 Shell 手册复制进系统提示词。

## Decisions

1. 系统提示词只描述路由原则：无需外部执行即可可靠完成的普通问答直接回答；当请求需要精确计算、数据转换、文件/网络/诊断执行才能可靠完成时，进入操作循环并选择工具。
2. Shell 的具体选择标准放进工具描述：若命令行相对纯推理或手机 UI 更准确、高效、可验证，则优先使用；列举计算、文本/结构化数据、文件、网络、诊断场景。
3. 工具描述同时声明负面边界：普通知识问答、解释、建议和创作不为“能跑命令”而调用 Shell；已有更合适的专用工具时优先专用工具。
4. 通过源码级测试锁定系统提示词和工具描述中的关键语义，避免以后再次退化为绝对禁用工具。
5. “是否简单”只影响是否需要任务清单，不作为是否调用其他工具的判断标准；系统提示词移除“简单任务直接完成”，保留更窄的 `todo_update` 使用条件。
6. 当前日期、时间、星期和时区属于动态事实。不新增专用时间工具；在简洁的 `shell_execute` 描述中要求通过现有 `date` 命令查询，不得猜测。参考 OpenMinis 将 Android 当前 UTC 偏移以 POSIX `TZ` 注入 PRoot，保证 `date` 返回手机本地时间。
7. 参考 OpenMinis 保持顶层 Shell 描述简洁：只保留运行环境、选择边界、时间查询规则、Android 命令发现入口和结果使用约束，删除 URI 与子命令示例。

## Risks / Trade-offs

- [模型可能对简单算术也频繁调用 Shell] → 描述限定为“需要精确、可验证或批量处理”，普通问答继续直接回答。
- [提示词仍与模型自主判断有关，不能保证每次都选 Shell] → 使用明确正反例和“优先”措辞，不引入额外路由器。
- [工具描述增加少量 token] → 保持为一段紧凑说明，不加入运行手册。

## Migration Plan

随新版 JS bundle 生效；无需数据迁移，回滚两处提示文案即可恢复。
